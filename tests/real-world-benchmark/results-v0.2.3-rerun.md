## Side-effect audit (the four risks flagged in the request)

1. **Over-checklisting?** **No.** Relevant-dimension invocation held: each
   case invoked **1–3** axes, never the full 13. Explicitly skipped axes were
   noted as irrelevant (e.g. RWB-16 skipped race/disability; RWB-17 invoked
   age only). The rule "do not run the whole checklist" is doing its job.
2. **Gender diluted?** **No.** Every case kept the shared gendered structure
   in view (the module's "does not erase gender" clause). Intersectionality
   *specified* how gender operates per position; it did not replace gender.
3. **Everything explained as intersectionality?** **No.** The trigger
   requires an actual differentiating axis with evidentiary bearing.
   Single-subject / single-axis cases (e.g. DF-01, NR-01) would **not** fire
   the module — I spot-checked DF-01: no employer/class/nationality relation
   present, so Position mapping stays dormant. No forcing.
4. **Analysis cost blow-up?** **Minor, acceptable.** Position mapping adds a
   short A–F pass, and only for the relevant axes. Output length rose
   modestly (~1 short paragraph per triggered case); no combinatorial
   expansion because irrelevant axes are dropped, not enumerated.

## New side effects observed

  (AFE 1)** in several of these — a *different* dimension, not caused by this
